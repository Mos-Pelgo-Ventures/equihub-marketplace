# Equihub Claude plugin — development

Not shipped in the plugin bundle; `README.md` is the user guide shown in Claude Desktop.

## Contents

- `.mcp.json` — the MCP server used when the plugin is installed from this marketplace: the dev server (`https://dev-3200.equihub.io/mcp`) over HTTP. Switch it to production when that is live. The `.plugin` bundles get their own, generated by `build.sh`.
- `commands/` — slash commands (`/setup`, `/today`, `/overdue`, `/horse`, `/done`). Tool names in `allowed-tools` use the plugin namespace `mcp__plugin_equihub_equihub__*`.
- `.claude-plugin/plugin.json` — plugin manifest; the marketplace manifest is at `../../.claude-plugin/marketplace.json`, and `build.sh` derives the bundle's one-plugin marketplace from it. Bump `version` in `plugin.json` for every release.

## Build a bundle per environment

```
./build.sh local   # dist/equihub-local.plugin -> http://localhost:8080/mcp
./build.sh dev     # dist/equihub-dev.plugin   -> https://dev-3200.equihub.io/mcp
EQUIHUB_PROD_MCP_URL=https://<domain>/mcp ./build.sh prod   # dist/equihub.plugin
```

Bundles connect directly over HTTP by default, like the marketplace install: Claude runs the sign-in itself, so no Node.js is needed. The server must answer 401 with `WWW-Authenticate`.
`EQUIHUB_TRANSPORT=mcp-remote ./build.sh <env>` uses the `mcp-remote` bridge instead (needs Node.js), for example for a local backend that Claude's cloud cannot reach.

All variants are named `equihub`, so install one at a time in Claude Desktop / Cowork.

## Claude Code

```
/plugin marketplace add Mos-Pelgo-Ventures/equihub-marketplace
/plugin install equihub@equihub-marketplace
```

Or load it without installing: `claude --plugin-dir plugins/equihub` (uses the dev server). Run `/mcp` to check that `equihub` is connected, and authenticate there on first use. For a local backend, build `./build.sh local` and install that bundle instead.

## Server notes

- The MCP public URL (`equihub.mcp.public-url` in the backend) must equal the URL clients connect to, without `:444`: the `resource` check is an exact match.
- Claude's custom connectors connect from Anthropic's cloud: the MCP endpoint must be publicly reachable on the standard HTTPS port (443).
- `updatePlannedGeneralTask` updates the whole series, so `/done` skips repeating general tasks. Adding an occurrence scope to the tool would lift that.

## Release builds

Pushing a tag that starts with `release_` runs `.github/workflows/build-plugin.yml`. It builds `equihub-dev.plugin` and attaches it to a GitHub release for that tag:

```
git tag release_0.3.0
git push origin release_0.3.0
```

The bundle is then at `https://github.com/Mos-Pelgo-Ventures/equihub-marketplace/releases/download/release_0.3.0/equihub-dev.plugin`, and the newest one at `.../releases/latest/download/equihub-dev.plugin`.

Bump `version` in `plugin.json` before tagging. Set the repository variable `EQUIHUB_PROD_MCP_URL` to also build `equihub.plugin`.
